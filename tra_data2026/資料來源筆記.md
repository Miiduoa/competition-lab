# 臺鐵數據力 2026｜資料來源筆記

對應作品：**鐵道旅運負荷預測決策支援系統（RailFlow-DSS）**  
議題：**議題 2 旅途探索家**（運輸本業／臺鐵假期）  
用途：填寫官方「資料運用來源細節表」、支撐企劃書方法與評分「資料使用與分析」。

---

## 一、選定策略（為何這些資料）

| 優先 | 資料 | 理由 |
|------|------|------|
| **P0 核心（必用）** | 臺鐵每日各站點進出站人數 | 直接量化旅運負荷；日頻、可預測、機關＝臺鐵；完美對齊 DSS「預測→解釋→建議」 |
| P1 | 臺鐵車站基本資料集 | 站名／GPS／地址；分群、地圖、觀光站標記 |
| P1 | 定期時刻表／每日時刻表 | 班次／停靠代理變數＝運能側特徵 |
| P1 | 營運通阻 | 事件日與恢復曲線；異常解釋 |
| P2 | 即時列車位置 | 決選延伸：延誤與站負荷聯立原型 |
| P2 | 線別／車種別／各站起訖量年統計 | 長期結構校準、簡報背景圖 |
| 選用外部 | 國定假日曆、氣象日雨量、公開活動 | 連假／天候／活動特徵（須於來源表「其他來源」揭露） |

> 資格底線：至少 **1 筆**「國營臺灣鐵路股份有限公司提供之開放資料」（data.gov.tw 或 TDX）。本企劃以 **8792 進出站人數** 為主證據，其餘為加分與可解釋性。

## 二、核心資料集（填來源表用）

### 1）臺鐵每日各站點進出站人數【主資料】

| 項目 | 內容 |
|------|------|
| 資料主題 | 臺鐵每日各站點進出站人數 |
| 出處說明 | 政府資料開放平臺（提供機關：國營臺灣鐵路股份有限公司） |
| 來源網址 | https://data.gov.tw/dataset/8792 |
| 授權 | 政府資料開放授權條款－第 1 版 |
| 更新頻率 | 約每月 |
| 主要欄位 | `trnOpDate`（乘車日）、`staCode`（車站代碼）、`gateInComingCnt`（進站人數）、`gateOutGoingCnt`（出站人數） |
| 備註 | 2021/01/01 後請用 JSON；站碼請對照車站基本資料集；相關 https://data.gov.tw/dataset/33425 |
| 如何支撐提案 | **預測目標 Y**：各站日進／出／總負荷；建構滯後與滾動特徵；連假與尖峰 EDA；儀表板時間序列主圖 |
| 企劃書引用頁碼 | 【轉 PDF 後填實際頁碼，草稿約在「資料來源／表 2」章節】 |

**衍生欄位（自行計算，非原始欄）**

- `gateTotal = gateInComingCnt + gateOutGoingCnt`  
- `netFlow = gateInComingCnt - gateOutGoingCnt`（通學／觀光不對稱探索）  
- 與假日曆 join：`is_holiday`, `days_to_next_holiday`

## 三、TDX 使用注意

1. 至 https://tdx.transportdata.tw/ **註冊**並建立 API Key（Client Id／Secret）。  
2. 訪客模式限制多；正式分析請用會員金鑰。  
3. Swagger（TRA）：平台內 TRA basic service 文件。  
4. 在「資料運用來源細節表」可寫：出處「TDX 運輸資料流通服務平臺」，網址填對應 data.gov 資料集頁或 TDX 服務頁，並註明 API 名稱。

## 五、與提案邏輯的對照（評審視角）

```
進出站日資料 (8792)  ──►  預測目標與歷史曲線
        │
車站主檔 (33425)    ──►  可讀站名、分群、地圖
        │
時刻表 (156732 等)  ──►  運能／班次特徵
        │
通阻 (161157)       ──►  事件解釋與例外
        │
假日曆等            ──►  連假觀光尖峰（旅途探索家）
        ▼
RailFlow-DSS：預測 → 特徵／相似日解釋 → 整備建議文案
```

**敘事銜接（備審 DSS，但企劃獨立）**：零售 DSS 是「銷量→補貨建議」；本賽是「站負荷→疏運／場站建議」。方法論同構（baseline、時間切分、可解釋儀表板），**問題域與資料完全獨立**，故若未投其他賽可免填差異表；若有投稿相近賽，於 attach_5 強調資料來源、應用情境、成果呈現之差異。

## 六、下載與實作備忘

```bash
# 進出站：至 data.gov.tw/dataset/8792 下載 JSON／壓縮檔
# 車站：dataset/33425 JSON
# TDX：申請 Key 後呼叫 Station / GeneralTrainTimetable / Alert 等
```

- 建模前先抽 1–2 站做管線煙測（站碼 join、日期型別、缺值率）。  
- 儀表板顯示「資料截至日期」，避免評審質疑時效。  
- 晉級後若申請內部資料：另簽保密、結束銷毀——海選企劃勿依賴未取得資料。
